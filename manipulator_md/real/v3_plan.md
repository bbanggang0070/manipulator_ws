## 2. 고칠 것 셋 — 전부 실측 근거가 있다

### ① 끝내기 — 놓은 뒤 곧장 rest, 그리고 **2초 정지**

평가에서 **42%(25/60)가 60초 타임아웃**이었고, **그중 18건은 올바른 칸에 넣기까지
성공한 뒤**였다. 마지막 자세가 rest 에서 중앙 **134°** 벗어나 칸 위에 머물렀다
(영상 확인: trial 41 · 13).

원인은 수집본에 있다.

```
v2 에피소드 끝 자세가 시작 자세에서 벗어난 정도: 중앙 7.7° · 최대 61.3°
   5° 이내 복귀:  67/250 = 27%
  10° 이내 복귀: 159/250 = 64%
놓은 뒤 남은 시간: 중앙 4.4s (3.2~6.8s)
```

**복귀 도중에 녹화가 끝났다.** GR00T 에는 종료 신호가 없어 "이제 멈춰라"를 오직
궤적으로만 배우는데, 그 궤적이 끝나다 말았다.

> **규칙.** 놓은 뒤 **확인하러 머물지 말고 곧장 rest** 로 간다. rest 에서
> **2초 멈춘 뒤** 녹화를 끝낸다.
>
> 2초 × 30fps × 120ep = 약 **7,200 프레임의 "rest 에 머무름"** 이 생긴다.
> v2 에는 이 상태가 사실상 0 이다 — 모델이 처음 보는 종류의 신호다.

### ② 파지 높이 — eraser 를 눕힘/세움 번갈아

| 물체 | 재파지율 | 파지 시 shoulder_lift | 파지 폭 |
| --- | --- | --- | --- |
| **eraser** | **20%** | **+4.0°** | **12.7** |
| marker | 12% | −3.6° | 6.8 |
| 큐브 6종 | 4~8% | −3.7 ~ −11.3° | ~9.0 |

eraser 는 재파지율 1위(큐브의 3~5배)이고 **파지 자세가 유일한 outlier** 다.
납작해서 책상에 바싹 붙기 때문이고, 이것이 "gripper 가 책상에 닿으면 멈춤"의 정체다.

그 결과가 평가의 `eraser → marker 3/6` 이다. **생김새 문제가 아니다** — marker 는
검은 펜, eraser 는 흰 상자로 사람은 전혀 헷갈리지 않는다. 파지가 불안정해
행동이 안 정해졌고, 그래서 가장 집기 쉬운 marker 로 샜다(marker 가 오답 5건을
끌어갔다: eraser 3 · screwdriver 1 · glue stick 1).

> **규칙.** eraser 를 **세워서** 놓는다(v3 36행 전부). 계획표가 행마다 지시한다
> (`pose_hint` 열). 세우면 파지 높이가 올라가 책상에 닿지 않는다.
>
> 눕힘은 v2 에서 **88회 등장**으로 이미 충분하다. 거기에 세움 36회를 더해
> 두 자세를 덮는다. 어느 자세든 **책상에 닿지 않는 높이에서 정교하게** 집는다.
>
> ⚠️ **자세는 궤적으로 확인할 수 없다.** 파지 시 lift 의 편차가 eraser 14.0° ·
> 큐브 13.6° 로 같은데, 그 편차는 자세가 아니라 **물체를 놓은 위치** 때문이다.
> 검증기가 잡아 줄 수 없으므로 사람이 계획표대로 지키는 수밖에 없다.
>
> ⚠️ 평가도 **세운 eraser 만** 잰다(`cleanup_eval.py` 의 `POSE_VARIANTS`).
> 눕힌 eraser 성능은 이 평가에서 안 나온다 — 보고서에 범위를 적을 것.

### ③ red ↔ orange — **학습엔 두고 평가에서만 분리**

v2 수집본 실측(ep18 프레임, 13×13 픽셀 중앙값):

```
red cube     색상 H=  4°   채도 33%
orange cube  색상 H= 22°   채도 42%      → 차이 18°
green cube   색상 H=158°   채도 75%   (대조)
```

표준 red↔orange 간격이 30° 인데 **18°** 이고 둘 다 채도가 낮다. 평가에서
`orange` 지시의 **40%(4/10)** 가 red 로 샜고, 그 4건이 물체 오답 10건의 40% 였다.
**한 쌍이 물체 축 전체를 끌어내린다.**

> **결정.** 학습에는 둘 다 둔다 — 구별을 배울 기회를 없애지 않는다.
> **평가에서만 같은 화면에 두지 않는다**(`cleanup_eval.py` 의 `EXCLUSIVE`).
> 재려는 것은 "지시문을 읽는가"이지 "18° 색차를 가르는가"가 아니다.
>
> ⚠️ **보고서에 범위를 명시할 것** — "red/orange 를 함께 두지 않은 조건에서 N%".
> 이 조건을 빼먹으면 수치가 실제보다 좋아 보인다.
>
> ⚠️ 학습에 쓰는 hue 증강 ±5.4°(`CJ_HUE=0.015`)가 이 18° 간격의 **30%** 를 먹는다.
> 이 쌍의 구별을 진지하게 노린다면 `CJ_HUE=0.005` 로 더 낮출 것.

## 4. 학습

```bash
./prepare_cleanup_real.sh          # 전송·변환·게이트(지시문 40종 · 4색 생존)
SMOKE=1 ./train_cleanup_real.sh    # 출발점 확인 — loss 1.05~1.13 이어야 한다
./train_cleanup_real.sh            # EPOCHS=8
```

| 항목 | 값 |
| --- | --- |
| 데이터 | 370ep · 약 249,700 frames |
| 출발점 | `nvidia/GR00T-N1.6-3B` — **파운데이션에서 새로** |
| 학습량 | EPOCHS=8 → 약 **31,000 step** · 약 **22시간** |
| 체크포인트 | 4,000 step 마다 8개 |
| 색 증강 | bri 0.3 · con 0.4 · sat 0.25 · **hue 0.015** |

6 epoch(23,500 step · 17시간)도 선택지다. sim 곡선은 6.5 epoch 부근이 최적이었고
v2 는 8 epoch 에서 목적지 96.2% 가 나왔다. 체크포인트가 8개 남으므로 과하게 돌려도
앞 지점을 쓸 수 있는 반면, 모자라면 다시 돌려야 한다 → **8 을 권한다.**

5090 에 v2 체크포인트(120 GB)가 남아 있다. 필요하면 비울 것(디스크는 1.6T 여유).

v2 대비 바뀐 것:

- **red ↔ orange 를 같은 화면에 두지 않는다**
- **eraser 는 세워서 놓는다** (`pose_hint` 열이 시행마다 지시)
- 타깃 카운트를 **시행 수 기준**으로 — v2 에서는 그룹당 1로 세어 orange 10회 vs
  red 2회로 벌어져 물체별 정확도를 비교할 수 없었다(이제 5~8회)
- `STOP_ON_REST=1` · `MAX_SEC=60`

### 무엇을 보면 성공인가

| 지표 | v2 | v3 목표 | 왜 |
| --- | --- | --- | --- |
| 타임아웃 비율 | **42%** | **< 15%** | ①의 직접 검증 |
| `eraser` 정확도 | **33%** (2/6) | **> 70%** | ②의 직접 검증 (세운 자세 기준) |
| 물체 축 | 71.7% | **> 85%** | ①②③ 합산 |
| 목적지 축 | 96.2% | **유지** | 떨어지면 회귀 |

목적지 축이 떨어지면 v3 가 손해다 — 그때는 v2 체크포인트로 되돌린다.

## 6. 알고 있는 위험

**① 상충하는 시연.** v2 의 250ep 은 복귀 도중 끝나고 v3 의 120ep 은 rest 에서
멈춘다. 같은 상태(놓은 직후, 칸 위)에 **서로 다른 행동**이 붙은 데이터가 되며,
깨끗한 끝맺음은 전체의 32% 다. 모델이 평균을 내어 더 머뭇거릴 수 있다.

→ 타임아웃이 안 줄면 **v2 에피소드를 릴리스 직후에서 잘라** 애매한 복귀 구간을
   빼는 수술을 한다(수집 시간 0). 그 뒤 다시 학습한다.

**② 평가 범위가 좁아졌다.** red↔orange 를 빼면 물체 축이 구조적으로 올라간다.
v2 와 직접 비교하려면 **같은 배제를 적용한 v2 수치**를 함께 보아야 한다
(v2 60시행에서 그 쌍이 함께 나온 시행을 빼고 재계산하면 비교 가능).

**③ eraser 는 세운 자세만 평가한다.** 눕힌 자세는 v2 데이터(재파지 20%)에
의존한 채 측정되지 않는다. 최종 데모에서 눕혀 놓을 일이 있다면 별도로 봐야 한다.

**④ 120ep 이 충분한가는 모른다.** 끝맺음은 새로운 종류의 신호라 적은 양으로도
들을 수 있지만, 근거는 없다. ①의 지표(타임아웃 비율)가 바로 답을 준다.
