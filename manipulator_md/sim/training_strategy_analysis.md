## 2. 왜 C가 최선인가 — "다양성 > 양"

같은 200ep이라도 **무엇으로 채우느냐**가 결정적이다.

```
Case A: [기존 분포 100ep] + [같은 분포 100ep 추가] = 200ep
        → 로봇이 이미 아는 것을 더 많이 반복 연습

Case C: [기존 분포 100ep] + [취약 축 보강 100ep] = 200ep
        → 로봇이 못 하는 것을 집중 연습
```

비유:
- **A** = 수학 시험에서 1~5번을 풀 줄 아는 학생에게, 1~5번 연습문제를 100장 더 줌
- **C** = 같은 학생에게, 틀린 6~10번 유형의 연습문제를 100장 줌

### A가 C보다 성능이 높을 수 있는가?

**거의 불가능하다.** C는 기존 100ep을 **유지**하면서 취약 축 100ep을 **추가**하므로,
기존 분포 성능은 유지되고 취약 축 성능만 올라간다.

| 지표 | A (같은 분포 ×2) | C (기존 + 취약 보강) |
|---|---|---|
| 학습분포 SR | 소폭 상승 (이미 80%라 천장 효과) | 유지 (기존 100ep이 커버) |
| **OOD SR** | **거의 변화 없음** (같은 분포를 반복해도 새 축을 배울 수 없음) | **유의미 상승** (취약 축 직접 학습) |

A가 C를 이기려면 "기존 분포의 데이터를 더 많이 보는 것이 **보지 못한 축**의 성능을 올린다"는
논리가 성립해야 하는데, 이는 VLA 사전학습 백본의 자발적 일반화에 의존하는 것이고,
선행연구에서 이 효과는 **미미하다**고 일관되게 보고되었다.

> **결론: C는 A보다 모든 면에서 같거나 낫다.** A의 유일한 장점은 "이미 데이터가 준비되어 즉시 시작 가능"이라는 **시간**뿐이다.

## 3. Resume(B, D)의 문제 — 무엇이, 왜 발생하는가

### 문제 ①: Cosine LR이 이미 바닥

GR00T 학습은 **cosine decay** LR 스케줄을 사용한다:

```
lr(t) = lr_min + 0.5 × (lr_max - lr_min) × (1 + cos(π × t / T_total))
```

40k steps에서 학습을 마쳤으면, 스케줄러가 `t/T = 40000/40000 = 1.0`으로 계산하여
**LR이 최솟값(≈0)**에 도달한 상태다.

```
[신규 40k]     lr: 1e-4 ──╲
                           ╲──── 점점 감쇠
                                 ╲___→ 0    (정상적으로 학습됨)

[resume +20k]  lr: ___→ 0 ▁▁▁▁▁▁▁▁▁▁▁▁▁▁  (이미 0 근처, 추가 학습 거의 안 됨)
                         ↑ 여기서 시작
```

LR 스케줄러를 리셋하면? → 갑자기 LR이 1e-4로 뛰어서 **이미 수렴한 가중치를 흔들어**
기존 성능이 붕괴한다.

**→ LR을 유지하면 학습이 안 되고, 리셋하면 기존 성능이 무너진다. 어느 쪽이든 문제.**

### 문제 ②: Catastrophic Forgetting (특히 Case D)

Case D에서 취약 축 데이터를 새로 넣고 resume하면:

```
v3@40k 모델 상태: "기존 분포(빨간 큐브, 특정 위치)를 잘 파지하는 가중치"
        ↓
취약 축 100ep 주입 (예: 극단 위치, 새 색상)
        ↓
모델이 새 데이터에 맞추려고 가중치를 수정
        ↓
🔴 기존에 잘 하던 것(기존 위치 파지)의 가중치가 덮어씌워짐
        ↓
"새 축은 조금 나아졌는데 기존 성능이 떨어짐" = catastrophic forgetting
```

신규 학습(C)에서는 **기존 100ep + 취약 100ep을 동시에 섞어서** 처음부터 학습하므로,
모델이 양쪽을 **균형 있게** 배운다. Resume은 시간순으로
"먼저 기존 → 나중에 취약"이므로 **나중 것에 편향**된다.

### 문제 ③: Optimizer State 불일치

Adam 옵티마이저는 각 파라미터마다 **1차/2차 모멘트(이동 평균)**를 유지한다.
이 모멘트는 기존 100ep 분포에 맞춰 튜닝되어 있는데, 갑자기 다른 분포의 데이터가 들어오면:

- 모멘트가 **잘못된 방향**을 가리킴
- 수렴까지 **추가 시간**이 필요하거나 아예 **발산**할 수 있음

신규 학습은 모멘트가 0에서 시작하므로 이 문제가 없다.

## 4. 각 방법의 역할 요약

| 방법 | 역할 | 소요 시간 | 최종 수치 적합 | 핵심 제약 |
|---|---|---|---|---|
| **A** | "양 부족?" 진단 | ~30h | ✅ 가능 (하지만 C가 상위호환) | 다양성 개선 없음 |
| **B** | "epoch 부족?" 진단 | ~10h | ❌ | LR 바닥 + 편향 |
| **C** ⭐ | 취약 축 직접 공략 | 수집 2~3일 + 학습 ~30h | **✅ 최적** | 수집 시간 필요 |
| **D** | "이 축이 효과 있나?" 빠른 방향 확인 | 수집 2~3일 + ~10h | ❌ | LR + forgetting + 편향 |

---

## 5. 추천 전략

> A를 건너뛰고 **C를 바로 하는 것이 가장 효율적**이다.
> A의 유일한 존재 이유는 "데이터가 이미 있어서 즉시 시작 가능"뿐이고, 성능 면에서 C를 이길 수 없다.
>
> Resume(B, D)는 **"싸게 원인을 알아내는 진단 도구"**로만 사용하고,
> 최종 비교표에 올릴 수치는 **반드시 신규 학습(C)**으로 생산한다.
