## 2. 왜 sim에서 먼저 하는가

실기 co-training까지 파이프라인은 이미 검증됐지만([report2](../sim2real/08_T1_sim2real/report2.md)),
sim 모델은 "간단한 추론 SR ~80%"만 확인했고 **일반화는 미검증**이었다.
일반화를 실기로 옮겨서 확인하는 것은 비효율적이다 — 실기는 리셋·정렬·카메라/팔 드리프트·
위치 커버리지 제약 등 교란이 크고 시행 비용이 높다(실제로 겪음).

sim은 조건을 프로그램으로 바꿔가며 **싸고·재현 가능하게·ground-truth 판정**으로 대량 평가할 수 있다.

### 🔄 5단계 — 평가 설계 (여기서 두 번 갈아엎음)

#### 5-a. 1차 설계 → **실패**
모든 조건을 **전체 랜덤 위에** 얹어 측정 → train/pos_ood/box_ood/color 전부 **45%**,
전부 고정한 것만 65%. **축을 바꿔도 숫자가 안 움직였다.**

**원인**: 베이스 랜덤화(박스·물리·조명)가 신호를 완전히 덮음.

#### 5-b. 2차 설계 — **통제 실험** (현재)
**기준(ref)을 고정하고 한 번에 한 축만** 켠다. 전 조건을 `-DR-Eval`에서 실행해
**씬 에셋은 동일**, 바뀌는 건 이벤트 랜덤화뿐.

| 프리셋 | 블록 | 박스 | 물리 | 조명 |
|---|---|---|---|---|
| `ref` | 학습범위 랜덤 | **고정** | off | off |
| `pos_ood` | **확대** | 고정 | off | off |
| `box_rand` | 학습범위 | **랜덤(학습범위)** | off | off |
| `box_ood` | 학습범위 | **확대** | off | off |
| `color_blue/green` | 학습범위 | 고정 | off | off |
| `full` | 학습범위 | 랜덤 | on | on | ← **학습 분포 = 합격 판정** |

**핵심 설계 근거**
- **블록 위치는 항상 랜덤** — 그건 랜덤화 요인이 아니라 **태스크 자체의 입력**이다.
  고정하면 10회가 같은 장면의 반복이 되어 측정이 무의미해진다.
- **seed 1984 고정** → 조건이 달라도 **같은 블록 위치 시퀀스**를 쓴다(실측 9/10 일치).
  즉 조건 간 비교가 **짝지은 비교(paired)** 라 블록 위치 변동이 상쇄된다.
- **`ref`는 학습 분포가 아니다** — 의도적으로 "비교의 원점"이다. 학습 분포는 `full`.
- `ref`의 박스 고정 위치(r 0.266, θ −0.97)는 블록 스폰 각도 범위 밖 → **블록-박스 겹침 원천 차단**.

#### 5-c. 겪은 사고와 방어장치
| 사고 | 영향 | 조치 |
|---|---|---|
| **5090에 씬 미배포** (로컬 fork만 수정) | v2 씬에서 측정한 무효 데이터 | sweep에 **씬 버전 검증** 추가(6요소 확인, 불일치 시 중단) |

R 키로 겹침 씬을 빼고, 판정을 **직접 눈으로** 했다.

| 조건 | 자동 | **GUI 육안** | Δ |

**OOD 평균 82.5% — OOD는 통과**했고, **학습 분포에서 막혔다**.

> 자동 라벨과 육안 판정을 60ep 전수 대조한 결과 **59/60 일치**.
> 즉 자동 sweep이 낮았던 주원인은 오표기가 아니라 **겹침 씬을 분모에 넣은 것**이었다.

"학습 분포 안에서도 못 한다 = 언더핏"이라 진단했으나, GUI에서는 **70% vs 80%로 −10%p**,
N=10 이항 노이즈 범위였다. **−40%p는 대부분 겹침 아티팩트였다.**

## 4. 원인 규명 — **블록-박스 근접**

> 이전 진단(언더핏 / 박스 랜덤화 병목)은 **철회**한다. 좌표를 기록해 재분석한 결과가 다르다.

### 4-a. 거리가 SR을 단조로 결정한다

| 블록-박스 중심거리 | SR |
|---|---|
| 0.00 ~ 0.12 m | **2/11 = 18.2%** 🔴 |
| 0.12 ~ 0.18 m | 7/14 = 50.0% |
| 0.18 ~ 0.25 m | 11/15 = 73.3% |
| 0.25 m 이상 | **15/17 = 88.2%** ✅ |

가까움/멂(중앙값 0.194m)으로 나누면 **39% vs 83%**. 겹침 8개를 이미 뺀 뒤의 수치다.

### 4-b. 블록 각도는 2차 요인

| | 가까움 | 멂 |
|---|---|---|
| θ < 0 (오른쪽) | **3/12 = 25%** | 7/8 = 88% |
| θ ≥ 0 (정면·왼쪽) | 8/16 = 50% | 17/21 = 81% |

**멀면 각도와 무관하게 80%대**다. 각도는 **가까울 때만** 추가로 악화시킨다.
θ 5구간 SR도 44.4 → 54.5 → 64.7 → 66.7 → 75.0%로 단조 증가(오른쪽일수록 나쁨).
학습 범위 θ ∈ (−0.7, 1.25)가 비대칭이라 오른쪽 각도 폭이 왼쪽의 절반뿐인 것과 일치한다.

### 4-c. 이 구멍은 **수집 필터가 만들었다** (측정으로 확인)

수집 데이터셋에는 물체 좌표가 없다. 대신 평가에는 `scenes.csv`로 실제 좌표가 남으므로,
**(픽셀 중심 ↔ 실제 좌표) 59쌍으로 영상→평면 변환을 맞춰** 수집 영상에 적용했다
(`analyze_dataset_geometry.py`). **보정 정확도: 블록 잔차 0.74cm, 홀드아웃 0.9~2.5cm.**

| 구간 | 학습 v3 (99ep) | 자연 분포(유효 37ep) |
|---|---|---|
| 0.08 ~ 0.12 m | 4.0% | 13.5% |
| 0.12 ~ 0.18 | 15.2% | 29.7% |
| 0.18 ~ 0.25 | 16.2% | 21.6% |
| 0.25 이상 | 64.6% | 35.1% |
| **근접(<0.18) 합** | **19.2%** | **43.2%** |

겹침권(<0.08) 제외는 올바르나(파지 불가), **0.08~0.18의 유효 근접까지 함께 걸러졌다.**

> **결론: 모델이 못 배운 게 아니라 덜 본 것이다.** 이전 두 가설(위치 커버리지, 언더핏)과 달리
> 이번엔 **진짜 "데이터에 없는 것"** 이고, 타깃 재수집이 정당해지는 첫 사례다.
>
> **측정 모델을 두 번 갈아엎었다**: 비례 환산(오차 6.8cm) → 호모그래피는 **잔차 24cm,
> 최대 1496cm로 발산**(사영 분모가 0을 지나며 폭발, 검출 이상치가 유발) → ① 검출을
> **최대 연결성분**으로 바꾸고 ② 분모 없는 **2차 아핀**(u, v, 1, u², v², uv)으로 교체해 해결.
> 카메라가 거의 top-down이라 2차항이 잔여 원근을 흡수한다.

→ 수집 사양은 **[collection_plan_v4.md](collection_plan_v4.md)**.

## 5. 측정 방법론 — 두 번의 교정

### 5-a. 겹침 씬 제외 (자동 → GUI 육안, 08-06)

박스·블록이 모두 랜덤이라 겹쳐 스폰되는 경우가 있다. 몬테카를로 20만 회 기준 **12.4%**,
실측(헤드리스 45ep)으로는 **17.8%**. 파지 자체가 불가능한 씬이라 지표에서 빼야 하는데
자동 sweep은 실패로 센다. 학습 수집 때 이런 ep를 수동 제외했으므로 분포 불일치이기도 하다.

```bash
xhost +local:root
~/blocktask_gui_cond.sh <조건> [ep수]     # R = 무효 씬 스킵, rerun 2카메라
SEED=7 ~/blocktask_gui_cond.sh full 20    # 시드 바꿔 독립 표본 누적
```
> 같은 명령을 두 번 돌려도 표본이 늘지 않는다 — 시드가 고정이라 **같은 씬 재생**이고,
> 시작 시 출력 폴더를 지운다. **NUM을 키우거나 SEED를 바꿀 것.**

**측정 조건 6종**: `ref, pos_ood, box_rand, box_ood, color_blue, color_green` (+ 판정용 `full`)
- `light_dr` 제외 — **효과 없음 실측**. 라이트박스가 씬을 감싸 `sky_light`
  (DomeLight, `visible_in_primary_ray=False`)가 렌더에 거의 영향 없고, ref와 ep별 밝기가
  175.9/180.3/176.8…로 동일. 실제 조명 변동은 `reset_lightbox_light_exposure`가
  **모든 조건에 이미** 적용 중(TaskEventCfg 기본).
- `phys_dr` 제외 — −20%p로 노이즈 범위.

### 5-b. 성공 판정 결함 수정 (→ 무인 측정 가능, 08-06)

`mdp/terms.py::vial_placed_on_rack`의 성공 플래그는 아래가 **동시에 참인 순간에만** 서고,
한 번 놓치면 에피소드 내내 재평가되지 않는다.

```python
vial_is_placed = (is_vertical & position_ok
                  & vial_was_grasped_recently   # 최근 N step 내 접촉 이력
                  & (~vial_grasped_now) & (~in_warmup) & (~_vial_placed_flags[...]))
```

`grasp_history_window=20`이라 **그리퍼가 떨어진 뒤 20 step 안에** 블록이 경계 안에 있어야 했다.
놓인 뒤 튀거나 굴러 20 step을 넘기면 이력이 만료돼 **영구 미판정**.
실측: `full` 40ep 중 **3ep**(1984-ep06/ep17, s7-ep06)가 박스 안에 100+ step 있었는데 fail.

**수정**: `grasp_history_window` 20 → **1000**(에피소드 최대 900 초과) → 링버퍼가 에피소드
전체를 덮어 "이번 ep에 한 번이라도 잡았는가"가 된다. 리셋 시 clear되므로 ep 간 누수 없음.

**검증**: 수정 후 45ep 무인 측정에서 **오표기 0건**(사용자 전수 확인).
→ 이제 자동 라벨을 신뢰할 수 있고, **사람 없이 대량 측정이 가능하다.**

```bash
~/blocktask_headless_scenes.sh full 45 11     # 무인, 약 30분, scenes.csv 동시 기록
```

### 5-c. 씬 좌표 기록 (`scenes.csv`, 08-06)

실패 ep가 **어느 배치**였는지 사후에 알 수 없어 원인 분석이 불가능했다.
`lerobot_eval.py`가 에피소드 시작 시 다음을 기록하도록 했다:

```
ep, outcome, steps, block_r/theta/x/y, box_r/theta/x/y, box_yaw, block_box_dist
```

**§4의 원인 규명은 전적으로 이 기록 덕분이다.** 이전까지는 영상 픽셀로 추정할 수밖에 없었고,
그래서 seed7 20ep만 보고 "근접 가설 철회"라는 **잘못된 결론**을 낸 적이 있다
(그 20ep에는 최소 거리가 0.085m라 근접 표본이 거의 없었다).

### 5-d. 씬 파일 드리프트 방지

복원을 **불변 기준본**(`vials_to_rack_env_cfg.py.v3base`)에서만 하도록 변경.
기존 방식은 실행 시점 파일을 백업했는데, 비정상 종료로 조건이 적용된 채 남으면
다음 실행이 **그 오염본을 기준으로** 백업/복원해 드리프트가 영구화됐다.
→ 실제로 5090이 `ref` 상태로 굳어 있었다(측정 결과에는 영향 없음, 프리셋이 전부 덮어쓰므로).

## 6. 다음 단계 — v4 타깃 수집

원인이 특정됐으므로 분기 진단(`box_pos_only`/`box_yaw_only`)은 **불필요**해졌다.
분해할 −40%p 자체가 겹침 아티팩트였다.

**계획 전문: [collection_plan_v4.md](collection_plan_v4.md)**

| 항목 | 값 |
|---|---|
| 블록-박스 중심거리 | **0.08 ~ 0.18 m** |
| 블록 각도 | **θ<0에 50% 배분** (자연 36%) |
| 박스·물리 | 기존 랜덤 그대로 (실패와 무관) |
| 신규 수집량 | **65 ep** (~1.5h) |
| **데이터셋** | **200ep** = v3 100 + 잔여에서 근접선별 35 + 신규 65 |
| 근접 비율 | **59.5%** (v3 현재 19.2%, 자연 43.2%) · 원거리 81ep로 v3의 80 유지 |
| 학습 | **86k** (66.1 epoch, 약 65h) |

**231ep를 전부 쓰지 않는다.** 오래된 원거리 데이터는 분모만 키워 근접 비율을 희석시킨다
(295ep면 39.2%, 200ep면 59.5%). 원거리는 이미 83~88%라 데이터 양이 병목인 구간이 아니다.

**구현이 필요하다**: 현 씬은 블록·박스를 **독립 샘플링**해 목표 구간 자연발생률이 30%다.
그대로면 60ep를 얻으려고 200ep를 시연해야 한다. → `reset_block_near_box()`로 조건부 샘플링
(박스를 먼저 뽑고 그 주변에 블록 배치), 수집 전용 task `...-Near`로 분리해 기존 경로 불변.

> **수집 규칙**: 벽에 닿거나 겹치면 제외하되, **"붙어 보여서 어렵다"는 이유로 빼지 말 것.**
> 그게 정확히 메우려는 구멍이다.

### resume vs 신규 학습 (결론: 신규)

GR00T는 `ShardedMixtureDataset(IterableDataset)`이고 trainer가
*"stateful samplers rely on global_step"* → **데이터가 바뀌면 샘플러 상태가 어긋난다.**
cosine LR도 40k에서 0으로 완주해 resume은 **warm restart**다. 상세 [training_plan.md §2](training_plan.md).

**스텝 수 함정**: v3 100ep 40k = 65.8 epoch인데, 295ep를 40k로 돌리면 **22 epoch**으로
오히려 더 언더핏된다. epoch 정합은 약 126k.
