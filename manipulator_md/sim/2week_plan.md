## 1. 계획 변경 이력 — 무엇을 왜 바꿨나

### 변경 ① 색상 다양화 → **위치·박스 랜덤화** (08-04)

| | 원안 | 변경 후 |
|---|---|---|
| 수집 | 큐브 5색 × 50ep = **300ep** | 빨강 고정 + **위치·박스 다양성 100ep** |
| 근거 | (가정) 색이 일반화에 중요 | **실측**: v2에서 색은 강건(파랑 70/초록 90), 위치만 붕괴(10~30%) |

→ 다양성 예산을 **실측된 약점**에 몰아줌. 색 수집은 낭비였을 것.

### 변경 ② 평가 설계: 전체 랜덤 위 측정 → **통제 실험** (08-06)

| | 1차 설계 | 2차 설계 |
|---|---|---|
| 방식 | 모든 조건을 전체 랜덤 위에 얹음 | **기준(ref) 고정 + 한 축만 변경** |
| 결과 | train/pos_ood/box_ood/color **전부 45%** | ref 90% ↔ pos_ood 40% ↔ box_rand 50% |
| 문제 | 베이스 랜덤화가 신호를 덮어 **축 분리 불가** | 축별 기여가 선명하게 분리됨 |

### 변경 ③ 자동 SR → **GUI 육안 판정** (08-06)

자동 sweep 수치를 그대로 못 쓰는 이유 2가지가 확인됨:
1. **success/fail 오표기** — `terminated and not truncated` 기준이라, 눈으로 성공해도
   성공 termination이 안 걸린 채 timeout되면 `fail`
2. **블록-박스 겹침 12.4%** (몬테카를로 20만 회) — 파지 불가능한 씬인데 실패로 집계되어
   **SR을 약 10%p 하향 편향**. 학습 데이터 수집 때는 이런 ep를 수동 제외했으므로 분포 불일치이기도 함

→ **R 키로 무효 씬을 빼며 육안 판정**으로 전환.

### 변경 ④ 측정 조건 9종 → **6종** (08-06)
- `light_dr` 제외: **효과 없음 실측**. 라이트박스가 씬을 감싸 `sky_light`가 렌더에 거의 영향 없고,
  ref와 ep별 밝기가 동일(175.9/180.3/…). 실제 조명 변동은 `reset_lightbox_light_exposure`가
  **모든 조건에 이미** 적용 중.
- `phys_dr` 제외: −20%p로 노이즈 범위. 실기 환경도 조명·물리가 안정적.

### 변경 ⑤ **v2 재측정 포기** (08-06)
v2는 카메라 오프셋 0으로 학습(08-04 18:47에 0.03/0.02로 변경), 박스 고정, 물리 DR 없음,
블록 범위도 다름. 현재 씬으로 재면 **씬 불일치를 재는 것**이라 무의미.
→ **v3 vs v3_200**에 집중(둘은 완전히 동일한 씬이라 변수가 데이터 양 하나).

### 변경 ⑥ **육안 GUI → 무인 측정으로 복귀** (08-06 저녁)
성공 판정 결함(`grasp_history_window=20`)을 고치자 자동 라벨이 신뢰 가능해졌다
(45ep 측정에서 오표기 **0건**). 육안은 조건당 10~25분 사람이 붙어야 해 표본 확대가 불가능했는데,
무인으로 45ep을 30분에 돌릴 수 있게 됐다. → **원인 규명에 필요한 N을 확보**.

### 변경 ⑦ **진단 방향 전환: 언더핏 → 블록-박스 근접** (08-06 저녁) ⭐
`box_rand` 50%(ref 90% 대비 −40%p)를 근거로 "언더핏"이라 진단했으나,
GUI 재측정에서 **70% vs 80%(−10%p)** 로 노이즈 범위였다. **−40%p는 겹침 아티팩트였다.**
좌표를 기록해(`scenes.csv`) 재분석하니 진짜 원인은 **블록-박스 거리**였다.
→ 2차 학습 계획을 "데이터 2배(v3_200)"에서 **"근접 구성 타깃 수집"** 으로 변경.

### 변경 ⑧ **분기 진단(box_pos_only/box_yaw_only) 취소** (08-06 저녁)
분해하려던 −40%p 자체가 아티팩트로 밝혀져 진단의 전제가 사라졌다.
프리셋은 만들어뒀으나 실행하지 않는다.

## 3. 현재 진단 — **블록-박스 근접** (언더핏 진단은 철회)

좌표 보유 **57ep**(seed7 20 + 무인 37) 기준.

| 블록-박스 거리 | SR |
|---|---|
| < 0.12 m | **18.2%** 🔴 |
| 0.12 ~ 0.18 | 50.0% |
| 0.18 ~ 0.25 | 73.3% |
| ≥ 0.25 | **88.2%** ✅ |

**단조 감소.** 가까움/멂(중앙값 0.194m)으로 나누면 **39% vs 83%**.
블록 각도는 2차 요인 — **멀면 각도 무관 80%대**, 가까울 때만 θ<0가 25% vs θ≥0가 50%.

**구멍의 출처를 측정으로 확인**: 학습 v3 82ep와 자연 분포 45ep의 첫 프레임에서
블록·박스를 색분할 검출해 거리 분포를 비교(같은 top 카메라).

| | 학습 v3 | 자연 분포 |
|---|---|---|
| <0.08 겹침권 | 1.2% | 17.5% |
| 0.08~0.18 | **20.9%** | **30.0%** |
| **근접(<0.18) 합** | **22.2%** | **47.5%** |

`<0.08` 제외는 올바르나(파지 불가), **0.08~0.18의 유효 근접까지 걸러졌다.**
→ **수집 필터가 만든 분포 갭**. 모델이 못 배운 게 아니라 **덜 본 것**.

## 4. 향후 계획 — v4 타깃 수집

전문: **[collection_plan_v4.md](collection_plan_v4.md)**

### 4-a. 구현 (선행)
현 씬은 블록·박스를 **독립 샘플링**해 목표 구간 자연발생률이 30%다.
그대로면 60ep 얻으려고 200ep를 시연해야 한다.
→ `reset_block_near_box()`로 조건부 샘플링(박스 먼저 뽑고 주변 0.08~0.18m에 블록),
수집 전용 task `Lerobot-So101-Teleop-Vials-To-Rack-Near`로 분리해 **기존 경로 불변**.

**배포 후 리셋 20회 캡처로 분포 검증(3분)은 필수** — 씬 미배포로 무효 측정한 전례가 있다.

### 4-b. 수집 사양

| 항목 | 값 |
|---|---|
| 블록-박스 거리 | **0.08 ~ 0.18 m** |
| 블록 각도 | **θ<0에 50% 배분** (자연 36%) |
| 박스·물리 | 기존 랜덤 그대로 (실패와 무관) |
| 수집량 | **60~70 ep** (~1.5h) |

> **"붙어 보여서 어렵다"는 이유로 빼지 말 것.** 벽에 닿지만 않으면 수집한다.
> 40~45ep는 과소 — 근접 비율이 34%까지만 오른다(60ep 38%, 70ep 40%).

### 4-c. 2차 학습

| 항목 | 값 |
|---|---|
| 데이터 | 231ep(기존 전부) + 65ep ≈ **295ep** |
| 방식 | **신규 학습** (resume 부적합) |
| 스텝 | **95k**(50 epoch, 71h) 또는 **126k**(66 epoch, 95h) |

> **resume 위험**(실측): GR00T는 `ShardedMixtureDataset(IterableDataset)`이고 trainer가
> *"stateful samplers rely on global_step"* → 데이터가 바뀌면 샘플러 상태가 어긋난다.
> cosine LR도 40k에서 0으로 완주해 resume은 **warm restart**.
>
> **스텝 함정**: v3 100ep 40k = 65.8 epoch. 295ep를 40k로 돌리면 **22 epoch**으로 더 언더핏.
>
> **귀속 한계**: "데이터 증가"와 "근접 보강"이 동시에 들어가 어느 쪽 효과인지 못 가린다.
> 목표가 ablation이 아니라 80% 돌파이므로 감수. 필요시 v3_200을 대조군으로 추가 학습.

### 4-d. 재평가 (무인, 사람 불필요)
```bash
for s in 21 22; do ~/blocktask_headless_scenes.sh full 45 $s; done   # ~1h
```

| 지표 | 목표 | 현재 |
|---|---|---|
| `full` 전체 | ≥80% | 61.4% |
| **근접(<0.18m)** | **≥70%** | **39%** ← 핵심 |
| 원거리(≥0.18m) | 유지 ≥80% | 83% |
| OOD 평균 | ≥70% | 82.5% ✅ |

원거리가 떨어지면 catastrophic forgetting → 데이터 비율 재조정.

### 4-e. 최종: sim2real
합격(SR≥80% / OOD≥70%) 시 진행. 서빙 스크립트는 **수정 불필요**(모델 경로만 인자로 전달).
```bash
ssh 5090 '~/serve_blocktask_n16_5090.sh gr00t_blocktask_v3_*/checkpoint-40000 start'
# 로컬: goto_home_real.py + ENSEMBLE=1 W=0.3 + real_pose_align 정렬 확인
```
실기는 zero-shot이므로 [report2 §5](../sim2real/08_T1_sim2real/report2.md) 선례대로
**co-training이 추가로 필요할 가능성이 높다**.

## 5. 위험 요소 — 실제 발생분과 대응

| 위험 | 실제 발생 | 대응·교훈 |
|---|---|---|
| Isaac Sim 크래시 | **2회** | `docker rm -f blocktask`로 좀비 정리(VRAM 회수) 후 새 폴더로 재개 → 손실 0 |
| USB(리더암) 분리 | **1회** (2.5h 세션 중) | 저장분 82ep 온전, 재연결 후 재개 |
| 5090 접속 불가 | **1회** | 유선/WiFi 동일 서브넷 충돌 → `ip route replace <5090>/32 dev <wifi>` |
| **씬 미배포** | **1회** | 로컬 fork만 고치고 5090 rsync 누락 → **무효 측정**. sweep에 **씬 버전 검증** 추가로 방어 |
| **잘못된 데이터로 학습** | **1회** | task 문자열 절단 버그, 학습 12분 시점 발견 → 재시작. **수집 후 메타 검증 필수** |
| **측정 영상 유실** | **1회** | 원격 정리 후 로컬 삭제 → 수집 스크립트를 **로컬 확보 검증 후 정리**로 변경 |
| **씬 파일 드리프트** | **1회** | 비정상 종료로 조건이 남은 파일을 다음 실행이 '기준'으로 백업 → `ref` 상태로 영구화. **불변 기준본(`.v3base`)에서만 복원**하도록 변경 |
| **측정 지표 결함** | **1회** | `grasp_history_window=20`으로 성공 판정이 영구 미발생(40ep 중 3ep). 1000으로 수정 후 오표기 0건 |
| **오진단** | **2회** | ① "언더핏"(겹침 아티팩트를 실력 차로 오독) ② "근접 가설 철회"(seed7 20ep에 근접 표본이 없어 반증으로 오독). 둘 다 **표본이 얇을 때 단정**한 것이 원인 |
| 데이터 부족 | 미발생 | 231ep 확보(목표 200 초과) |

**교훈**: 측정 도구를 먼저 신뢰 가능하게 만들었어야 했다. `scenes.csv`(좌표 기록)와
판정 결함 수정이 있었다면 오진단 2회와 GUI 육안 수 시간을 아꼈을 것이다.
