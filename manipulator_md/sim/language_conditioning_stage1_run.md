## 1. 갱신된 학습 예산

프레임이 135k가 아니라 **118,934**이므로 epoch이 바뀐다. effective batch 64 기준:

```
1 epoch = 118,934 / 64 = 1,858 step
```

| Run | 출발점 | 스텝 | epoch | 소요(1,333 step/h) |
|---|---|---|---|---|
| **A** (1순위) | `gr00t_blocktask_v4_200_n16_8bit/checkpoint-86000` | **25,000** | **13.5** | **약 19시간** |
| B (A 실패 시) | `nvidia/GR00T-N1.6-3B` 신규 | 60,000 | 32.3 | 약 45시간 |
| C (둘 다 무너질 때) | base + v4_200 혼합 `MIX=0.3` | 60,000 | — | 약 45시간 |

계획 문서의 11.9 epoch은 135k 가정이었다. **실제로는 13.5 epoch**으로, 오히려 더 돈다.
참고 사례(`so101-pi0-9task`)가 2.4 epoch으로 9태스크 어휘를 얻은 것을 생각하면 부족하지 않다.
부족 여부는 **§3 G4의 프로브 곡선이 아직 오르는 중인가**로 판단한다.

**저장 용량**: 체크포인트 9.2GB × `--save-total-limit 10` = 92GB.
보관본 {2k,4k,6k,10k,16k,25k} 6개 = 55GB. **5090에 150GB 이상 필요.**

## 3. 절차와 게이트

### P3 — 데이터 준비 (기계 약 40분)

```bash
./setup/sim/t1_task/prepare_blocktask_lang.sh all
```

전송 → 변환 → 병합 → 후처리 → 검증. `prepare_blocktask_v4_200.sh`와 같은 4단계에
두 가지 후처리가 반드시 붙어야 한다(빠뜨리면 학습 스크립트가 거부한다):

- `modality.json` — `front`/`wrist` 매핑과 `annotation.human.task_description ← task_index`
- `fix_stats_for_gr00t.py` — `stats.json`의 `count` 제거

**[G3] 지시문이 살아남았는가**

| 확인 | 합격 | 실패 시 |
|---|---|---|
| `meta/tasks.jsonl` 줄 수 | **100줄** (수집 실측) | 1줄이면 변환이 태스크를 접은 것 — **언어 학습 신호 0**, 여기서 중단 |
| `total_episodes` | 281 | 병합 누락 |
| `total_frames` | 118,934 | 〃 |

이 게이트가 §5 전체에서 가장 싸고 가장 중요하다. 1줄로 접히면 19시간이 통째로 무의미해진다.

---

### P4 — Run A 이어학습 (기계 약 19시간)

```bash
./setup/sim/t1_task/train_gr00t_blocktask_lang_n16_8bit.sh <DATA_ROOT> 25000
```

v4_200 스크립트와 다른 곳은 **한 줄**이다:

```
--base-model-path /workspace/models/gr00t_blocktask_v4_200_n16_8bit/checkpoint-86000
```

나머지 하이퍼파라미터는 그대로 둔다 — `global-batch-size 2` × `gradient-accumulation-steps 32`,
`lr 1e-4`, `warmup-ratio 0.05`, color jitter 동일. **한 번에 한 축만 바꾼다.**

저장 설정만 바꾼다: `--save-steps 2000 --save-total-limit 10` (계획 §6 — 언어가 언제 살아나는지
곡선을 공짜로 얻기 위함).

**[G4a] 이어학습이 실제로 됐는가 — 10 step 스모크**

`--base-model-path`에 로컬 경로를 주는 경로는 조용히 실패할 수 있다. 본 학습 전에 10 step만 돌려
**초기 loss가 base 수준(≫0.01)이 아닌지** 확인한다. base 수준이면 이어학습이 안 되고 처음부터
시작한 것이다.

**[G4b] 6k 체크포인트에서 기미가 있는가**

```bash
python setup/gr00t/probe_language.py --ckpt .../checkpoint-6000
```

| 비교 | 6k 기준 | 못 넘으면 |
|---|---|---|
| `red block` vs `blue block` | **≥2°** | 25k까지 돌리지 말고 §4로 — 기계 시간이 5시간에서 멈춘다 |
| 같은 문장 2회 | ≈0° | 프로브 자체가 잡음투성이라는 뜻 |

### P5 — 무인 평가 (기계 약 3시간, 사람 0)

`EVAL_PANEL_LANG` 10배치 × 3회 = 조건당 30ep. 계획 §7-2의 10조건.

**핵심은 대응쌍이다** — 조건 1↔2↔3↔4(같은 패널, 문장만 다름), 5↔6(같은 배치, 목적지만 다름).
같은 화면에서 문장만 바뀌므로 차이의 출처가 언어로 특정된다.

| 지표 | 우연 | 합격선 | 시행 |
|---|---|---|---|
| 프로브(색·이름·목적지) | — | **≥5°** | — |
| **물체 선택률** (조건 1~4) | 25% | **≥45%** | 120 |
| **목적지 선택률** (조건 5·6) | 50% | **≥65%** | 60 |
| 미완수 비율 | — | ≤40% | — |
| 안전 지표 (조건 9, 레거시 문장) | — | 기준선 9/10 대비 **−2 이내** | 30 |

조건 9가 중요하다 — **기존 배포 성능을 깨뜨리지 않았는지**를 본다. 언어를 얻고 pick-and-place를
잃으면 실기 확장이 막힌다.

**[G5] 위 표를 하나라도 못 넘으면 §4로 간다.**

---

### P5b — 미학습 색 일반화 (보너스, 주 판정선 아님)

G1(흰·분홍 큐브 동시 배치 후 하나 지시) · G2(흰 박스) · G3(둘 다).
**반드시 미학습 색 2개를 함께 놓는다** — 하나만 놓으면 색을 몰라도 "낯선 것 고르기"로 맞는다.

실패해도 P5 결과는 그대로 유효하다. 성공하면 실기 확장의 근거가 된다.

---

### P6 — 결정

G5 통과 → 실기 프롭 준비 + 실기 수집 착수.
G5 실패 → §4의 대응 중 택1, cleanup 태스크는 **색 기반 규칙으로 축소**하고 일정은 유지.

## 4. 실패 시 분기

| 증상 | 해석 | 대응 |
|---|---|---|
| G3에서 `tasks.jsonl` 1줄 | 변환이 태스크를 접음 | 변환 스크립트 수정 후 재변환. **학습 착수 금지** |
| G4a 초기 loss가 base 수준 | 이어학습 실패 | 체크포인트 경로·포맷 확인. 안 되면 Run B로 |
| G4b 6k에서 <2° | 굳은 모델이 안 풀림 | **Run B**(base에서 60k). 그 자체가 결론이다 |
| 프로브는 오르는데 선택률이 안 오름 | 언어는 읽지만 행동이 안 따라옴 | 스텝 증량 후 재평가 (+3일) |
| 선택률은 오르는데 조건 9가 −3 이하 | 기존 성능 잠식 | 혼합 학습(Run C, `MIX=0.3`) |
| 전부 실패 | 이 파이프라인에서 언어 조작 불가 | 색 규칙 기반으로 축소. **발표 일정은 유지** |
