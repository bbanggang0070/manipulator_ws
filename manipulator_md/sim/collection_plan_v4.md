# v4 타깃 수집 계획 — 블록-박스 근접 구성 보강

> v3@40k가 학습 분포(`full`)에서 **61.4%**(N=57)에 머문 원인을 실측으로 특정하고,
> 그 구멍을 메우는 데이터를 수집하는 계획.
>
> 작성 2026-08-06 · 관련: [README](README.md) · [학습 분기 계획](training_plan.md) · [2주 계획](2week_plan.md)

## 1. 원인 — 블록이 박스에 가까우면 실패한다

좌표 보유 57ep(seed7 20 + 헤드리스 37, 겹침 8개 제외) 기준.

| 블록-박스 중심거리 | SR |
|---|---|
| 0.00 ~ 0.12 m | **2/11 = 18.2%** 🔴 |
| 0.12 ~ 0.18 m | 7/14 = 50.0% |
| 0.18 ~ 0.25 m | 11/15 = 73.3% |
| 0.25 m 이상 | **15/17 = 88.2%** ✅ |

**단조 감소.** 가까움/멂(중앙값 0.194m)으로 나누면 **39% vs 83%**.

### 블록 각도는 2차 요인

| | 가까움 | 멂 |
|---|---|---|
| θ < 0 (오른쪽) | **3/12 = 25%** | 7/8 = 88% |
| θ ≥ 0 (정면·왼쪽) | 8/16 = 50% | 17/21 = 81% |

**멀면 각도와 무관하게 80%대**다. 각도는 가까울 때만 추가로 악화시킨다.
θ 5구간 SR도 44.4 → 54.5 → 64.7 → 66.7 → 75.0%로 단조 증가(오른쪽일수록 나쁨).

> 학습 범위가 θ ∈ (−0.7, 1.25)로 비대칭이라 오른쪽 각도 폭이 왼쪽의 절반뿐이다.

## 2. 이게 수집 필터가 만든 구멍임을 **측정으로 확인**

학습 데이터(v3 82ep)와 평가(헤드리스 45ep = 씬의 자연 분포)의 첫 프레임에서
블록·박스를 색 분할로 검출해 거리 분포를 직접 비교했다. **같은 top 카메라**라 비교 가능.

| 구간 | 학습 v3 | 평가(자연 분포) |
|---|---|---|
| < 0.08 m (겹침권) | **1.2%** | 17.5% |
| 0.08 ~ 0.12 | 4.9% | 7.5% |
| 0.12 ~ 0.18 | 16.0% | 22.5% |
| 0.18 ~ 0.25 | 32.1% | 20.0% |
| 0.25 이상 | 45.7% | 32.5% |
| **근접(<0.18) 합** | **22.2%** | **47.5%** |
| 중앙값 | 0.237 m | 0.191 m |

- `<0.08`(겹침권)이 1.2% vs 17.5% — **의도한 제외**이고 올바르다(파지 불가).
- 그런데 **0.08~0.18의 유효 근접 구간까지 함께 줄었다**(20.9% vs 30.0%).
  → 제외 판단이 겹침을 넘어 "붙어 보이는" 씬까지 걸렀다.

**결론: 학습 데이터의 근접 구성이 자연 분포의 절반 이하다.**
모델이 못 배운 게 아니라 **덜 본 것**이고, 이번엔 진짜 "데이터에 없는 것"이다.

> ⚠️ 픽셀→미터 환산은 평균오차 6.8cm로 거칠다(원근·깊이 무시). 구간 경계는 흐릿하지만,
> **두 집합에 같은 편향이 걸리므로 분포 비교 자체는 유효**하다. 중앙값 차이와 형태 차이가 근거다.

## 3. 수집 사양

| 항목 | 값 | 근거 |
|---|---|---|
| **블록-박스 중심거리** | **0.08 ~ 0.18 m** | 겹침(<0.08)은 파지 불가라 제외. 0.18 이상은 이미 80%대 |
| **블록 각도 θ** | **음수 구간에 50% 배분** (자연 비율 36%) | 근접+오른쪽이 25%로 최악 |
| 블록 반경 | 학습 범위 0.16~0.34 유지 | r 구간별 SR에 유의한 패턴 없음(73/50/65%) |
| 박스 위치·yaw | **기존 랜덤 그대로** | 박스 변수는 실패와 무관(실패·성공 평균 차 0.003) |
| 물리 DR | 기존 그대로 | 변수 고정 |
| **수집량** | **60 ~ 70 ep** | §4 |

### 수집 규칙
- 블록이 박스 **벽에 닿거나 겹친 씬은 제외**(기존과 동일) — 다만 이번엔 **닿지만 않으면 수집**한다.
  "붙어 보여서 어렵다"는 이유로 빼지 말 것. **그게 정확히 메우려는 구멍이다.**
- 파지 각도가 나오지 않으면 **박스 벽을 피해 비스듬히 접근**하는 시연을 보여줄 것.
  모델이 못 하는 게 그 동작이다.

## 4. 수집량 산정

현재 231ep 중 근접 비율 22.2% → 약 51ep. 목표는 자연 분포(47.5%)에 근접시키는 것.

```
(51 + N) / (231 + N) = 목표비율
```

| N | 최종 근접 비율 | 총 ep | 수집 시간(추정) |
|---|---|---|---|
| 40 | 33.6% | 271 | ~1시간 |
| **60** | **38.1%** | **291** | **~1.5시간** |
| 70 | 40.1% | 301 | ~1.8시간 |
| 96 | 45.0% (완전 정합) | 327 | ~2.5시간 |

**60~70ep 권장.** 완전 정합(96ep)은 수집 부담 대비 이득이 체감한다.
앞서 언급했던 40~45ep는 **과소**다 — 근접 비율이 34%까지밖에 안 올라간다.

## 5. 구현 — 조건부 샘플링이 필요하다

현재 씬은 블록과 박스를 **독립적으로** 뽑는다. 그대로 수집하면 목표 구간(0.08~0.18m)이
자연 발생률 30%라 **60ep를 얻으려고 200ep를 시연**해야 한다. 사람 시간이 비싸므로 코드로 해결한다.

### 문제: 이벤트 순서
```
VialsToRackEventCfg (base)      : reset_block_position   ← 블록이 먼저
VialsToRackEventDRCfg (하위)     : reset_basket_random    ← 박스가 나중
```
"박스 기준으로 블록을 뽑으려면" 순서가 반대다.

### 해법: 두 리셋을 **하나의 term으로 합친다**
`mdp/resets.py`에 `reset_block_near_box()` 신규 —

1. 박스를 기존과 동일하게 샘플링(arc 0.28~0.34, θ ±1.15, yaw ±π)
2. 목표 거리 `d ~ U(0.08, 0.18)`, 방향 `φ ~ U(0, 2π)` → 블록 = 박스 + d·(cos φ, sin φ)
3. 블록이 도달 범위(r 0.16~0.34, θ −0.7~1.25) 밖이면 **재추첨**(최대 50회, 실패 시 기존 방식 폴백)
4. θ<0 비율이 목표(50%)에 맞도록 φ 추첨에 가중

씬 설정은 `VialsToRackEventNearCfg(VialsToRackEventDRCfg)`로 분리하고
`reset_block_position = None`, `reset_basket_random = None`, 새 term 추가.
**수집 전용 task로 등록**: `Lerobot-So101-Teleop-Vials-To-Rack-Near`
→ 기존 수집/평가 경로는 **건드리지 않는다**.

### 검증 (수집 전 필수)
`capture_scene_conditions.py`로 20회 리셋 캡처 + 좌표 로그 →
거리가 0.08~0.18에 들어오고 θ<0 비율이 ~50%인지 확인. 약 3분.

> 지난번 "씬 미배포"로 무효 측정을 한 전례가 있으므로, **수집 시작 전 5090 배포와 값 확인을 반드시** 한다.

## 6. 학습 계획

| 항목 | 값 | 근거 |
|---|---|---|
| 데이터 | 231ep(기존 전부) + 60~70ep(타깃) ≈ **295ep** | 좋은 데이터를 버려 200에 맞출 이유 없음 |
| 방식 | **신규 학습** | resume은 LR 바닥·샘플러 상태·forgetting ([training_plan.md §2](training_plan.md)) |
| 스텝 | **약 126k** (66 epoch 정합) 또는 95k(50 epoch) | v3 40k=65.8ep, 200ep 40k=30.8ep — 스텝을 안 늘리면 더 언더핏 |
| 시간 | 약 95h(126k) / 71h(95k) | v3 실측 1,333 step/h |
| 하이퍼파라미터 | v3와 동일 | 변수를 데이터 하나로 |
| workers | 4 → **8** | v3 학습 중 GPU util 19% |

**⚠️ 귀속 한계**: "데이터 증가"와 "근접 보강"이 동시에 들어가 어느 쪽 효과인지 못 가린다.
목표가 ablation이 아니라 80% 돌파이므로 감수한다. 필요하면 나중에 v3_200(200ep, 같은 분포)을
추가로 학습해 대조군으로 쓸 수 있다.

## 7. 실행 순서

```
[1] reset_block_near_box 구현 + Near task 등록          (코드)
[2] 5090 배포 + 20회 리셋 캡처로 분포 검증               (3분)  ← 필수
[3] 타깃 수집 60~70ep                                  (~1.5h)
[4] v3 형식 변환 + 231ep와 병합 → 약 295ep              (~30분)
[5] 신규 학습 95k~126k                                  (71~95h)
[6] 무인 평가 full 45ep × 2시드 = 90ep                  (~1h, 사람 불필요)
[7] 합격(≥80%) 시 sim2real
```

[6]이 무인으로 가능해진 건 `grasp_history_window` 결함을 고쳤기 때문이다
(20 → 1000; 45ep 측정에서 오표기 0건 확인).

## 8. 판정 기준 (2차 학습 후)

| 지표 | 목표 | v3@40k 현재 |
|---|---|---|
| `full` 전체 | ≥ 80% | **61.4%** (N=57) |
| **근접 구간(<0.18m)** | **≥ 70%** | **39%** ← 핵심 지표 |
| 원거리(≥0.18m) | 유지 ≥80% | 83% |
| OOD 평균 | ≥ 70% | 82.5% ✅ |

근접 구간이 오르면서 원거리가 유지되는지를 본다.
**원거리가 떨어지면 catastrophic forgetting**이므로 데이터 비율을 재조정한다.
